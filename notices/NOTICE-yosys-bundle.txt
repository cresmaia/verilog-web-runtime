NOTICE of the Yosys bundle (yosys-wasm/)
=========================================

This is the notice of the Yosys bundle built by Cresmaia Inc. on 2026-10-25 (JST) without ABC (package version 0.68.1207-cresmaia.noabc.1).

Cresmaia Inc. (R8b, P5). This file is placed at yosys-wasm/NOTICE of a release that was built with `tools/build-site.mjs --with-yosys`.
The license texts it names are in yosys-wasm/LICENSES/ (the same directory has MANIFEST.tsv, which says from which upstream file and commit each text
was copied, byte for byte, or which lines of a file were copied). It is NOT part of the NOTICE of the Icarus Verilog files of the release; that NOTICE
does not cover the files below.

Every entry is a reading of the files named; it is not a legal opinion. Section 5 lists what was not checked. The records named below are in the source of the release
(runtime-source-<version>.tar.gz); the other records of the build and of the checks are not in it.

1. What the bundle contains
---------------------------
The files were built by Cresmaia Inc. from the sources of Yosys 0.68 (YosysHQ/yosys 38e001a, with the submodules named in section 4), by the build procedure of
YoWASP (https://codeberg.org/YoWASP/yosys, commit 89b0bc1: build.sh and package-npmjs.sh), with ABC NOT compiled in (cmake option YOSYS_WITHOUT_ABC=ON).
The package version is 0.68.1207-cresmaia.noabc.1 (prepare.py of YoWASP gave 0.68.1207; it was changed after that). The only change to build.sh is the cmake option above (records/p5/noabc/build/b1/build.sh.diff). Other differences are of place and tools: the build ran in a Docker container in /workspace/YoWASP/yosys, with the tools of Ubuntu 24.04 (cmake 3.28.3, GNU Make 4.3, flex 2.6.4, bison 3.8.2, ccache 4.9.1 with an empty cache, Python 3.12.3, git 2.43.0) and Node.js v22.23.3 with npm 10.9.9; the resource tar is cut down (section 1).
ABC (UC Berkeley) and its parts (saucy, the SAT solvers, CUDD, bzip2, zlib, Btor2Tools, kitty, ACD, eSLIM) are NOT in these files: no name of them is in
yosys.core.wasm, none of the words listed in records/p5/noabc/p5-materials/byte-terms.txt appears in any file of the bundle (zlib is not compiled in: cmake option
YOSYS_WITHOUT_ZLIB=ON), and the link of yosys.core.wasm had no input from the ABC tree (records/p5/noabc/p5-materials/names-diff.txt, records/p5/noabc/p5-materials/byte-terms.txt,
records/p5/noabc/build/b1/diag/trace.txt). The sha256 of each file served are in runtime.json (`yosys.sha256`).

4. Where the corresponding source is
------------------------------------
Of the licenses named in section 2, none is a copyleft license that asks for the source of the binary (symfpu's GPL option is not chosen; the output of bison 3.8.2
is under the special exception that the skeleton carries: bison.m4 lines 79-90 of the Ubuntu package bison 3.8.2+dfsg-1ubuntu0.24.04.1; the scanner of flex
is free of the flex copyright: /usr/share/doc/flex/copyright of flex 2.6.4-8.2build1). This holds for the components found by name, DWARF and link (section 5, item 1).
Cresmaia Inc. still records where the source is: Yosys 38e001a (https://github.com/YosysHQ/yosys), YoWASP 89b0bc1 (https://codeberg.org/YoWASP/yosys), the submodules
(slang 8acc660, sv-elab 3dddccd, fmt a00f82c, tomlplusplus a43ad37, cxxopts 4bf61f0, symfpu 5d5e508, boost_regex 2b3ac08), wasi-sdk 33 (llvm-project 4434dabb,
wasi-libc 161b319), jco jco-v1.19.0 (05555c1), wasmtime 4b6e961. ABC is not used (YosysHQ/abc 2a9e9c2 is not in the build).
The binaries were built by Cresmaia Inc. from these sources twice with the same result (all 83 output files have the same sha256 in the two builds:
records/p5/noabc/build/b1/sha256-artifacts.txt, records/p5/noabc/build/b1r/sha256-artifacts.txt); the differences from the YoWASP procedure are in section 1. The scripts of the build are not in the source of the release (section 4: no license here asks for the source).
The wasi-sdk 33 sysroot (wasi-libc, libc++, libc++abi, libunwind, compiler-rt builtins) was not built by Cresmaia Inc.: it is the prebuilt tarball
wasi-sdk-33.0-x86_64-linux.tar.gz (sha256 0ba8b5bfaeb2adf3f29bab5841d76cf5318ab8e1642ea195f88baba1abd47bce), whose VERSION file says "33.0+m" with wasi-libc 161b3195fc25 and
llvm 4434dabb6991. wasi-sdk applies four LLVM patches to its LLVM tree (libunwind, compiler-rt builtins, clang, libcxxabi: src/llvm-pr-*.patch in WebAssembly/wasi-sdk c10c050).

5. What was not checked
-----------------------
  1. Components that are linked but whose names are not distinct, or that carry no debug information: the lists above come from names, from the DWARF line table
     (354 translation units of the wasi-sdk sysroot only) and from the inputs of the link (records/p5/noabc/build/b1/diag/trace.txt: 809 lines of the link trace; 325 single objects and 484 archive
     members; of the 455 Yosys-side inputs, 324 are single objects and 131 are members of libsvlang.a; 354 inputs are from wasi-sdk).
     Yosys, slang and the other libraries were compiled without debug information; for them the names and the link inputs are the evidence. Other third-party code inside
     Yosys may exist. The first 80 lines of the 324 single objects of Yosys and sv-elab were read for notices (records/p5/noabc/p5-materials/linked-sources-notice-scan.tsv): 272 carry
     the ISC text, 3 the Apache-2.0 text (section 2), 5 the MIT text (json11, minisat), 1 public domain (sha1.cpp), 40 carry no permission text (covered by the COPYING of their tree),
     and 3 are generated (not read). Not read: the 20 .pmg sources of the generated code (peepopt_muldiv_c.pmg says it was authored by Silimate, Inc. under the ISC license);
     passes/cmds/sta.cc ("Adapted from" the nextpnr timing code, nextpnr being ISC); the notes in slang (util/Function.h, util/IntervalMap.h, numeric knuthDiv) that name LLVM as a model.
  2. The notices of the many contributors of Yosys are listed by file counts in index-Yosys-38e001a-copyright-lines.txt, which is generated, not an upstream text.
     The generated sources of bison and flex (frontends/verilog) and kernel/version.cc were not read as files (they exist only in the build).
  3. The sysroot of wasi-sdk 33 was not rebuilt from its sources; that the prebuilt libraries were made from the sources named above is not checked
     (the tarball carries no license text; the texts here are those of the upstream commits named in VERSION).
  4. core2: the adapter in jco 1.19.0 (packages/jco/lib/wasi_snapshot_preview1.command.wasm, 57236 bytes) was, as jco's script scripts/update-wasi-p2.sh reads, built from
     wasmtime commit 4b6e961 with rustc 1.82.0. That is an inference from the script and the producers value, not checked by rebuilding. The 130 function names of core2
     are all in the adapter of jco, except allocate_stack and realloc_via_memory_grow (helper names of the processing by `jco new`). The Rust crates compiled into the adapter
     were read from Cargo.toml and Cargo.lock only. That the output of jco (gen/yosys.js, core2 to core4) is covered by the license of jco is a reading, not checked with the authors.
  5. The license text of the musl files that carry "Sun Microsystems" and "Arm" notices were copied from one file of each form; other files of the same form were not compared.
  6. symfpu: BSD-3-Clause is chosen by Cresmaia Inc. (the file offers a choice of GPL V3 and BSD 3-Clause). boost_regex: the repository has no LICENSE file; the 56 files
     of include/ and the 2 files of src/ carry the Boost Software License 1.0 notice. The BSL says that the notice need not be reproduced for machine-executable object code.
  7. NOTICE files of upstream (Apache-2.0 section 4(d)): none was found in the root of F4PGA yosys-f4pga-plugins (7c89a55 and main), wasmtime 4b6e961, jco 05555c1, wasm-tools v1.245.1,
     rust 1.82.0, llvm-project 4434dabb, wasi-sdk c10c050, nor in the crates wasi 0.11.0, bitflags 2.6.0 and wit-bindgen-rust-macro 0.38.0 (records/p5/noabc/p5-materials/fetched/FETCHED.tsv).
  8. This notice is not a legal opinion.
